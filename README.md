# spinlens · 话术照妖镜

> **誓死捍卫大肥鱼 o7**

**一句话**：spinlens 是一个**受「大肥鱼保卫战」启发的互联网话术甄别器**——把一个 B 站视频的评论区过一遍，告诉你**有多少条评论在使用话术、分别是哪几类、原文是哪条**。

> **它是筛子，不是判决。** 输出只回答「哪条评论命中了哪一类话术」，不回答「谁在使坏」。

---

## 缘起

2026 年 9 月，B 站上围绕 DeepSeek 拟人形象（「男设」vs「鲸鱼娘 / 大肥鱼」）爆发了一场大规模争论。

翻评论区时我们注意到一个现象：**大量发言不是「观点」，而是「话术」**——和稀泥、假中立、扣帽、拿元概念定性。这些话术不生产信息，却会让讨论越吵越糊：你反驳的是内容，对方回应的是姿态；你想把一件事说清楚，最后变成互相定性。

**这个项目要做的不是帮谁赢，而是把这些手法照出来**——这就是中文名叫「照妖镜」的原因。

> 声明：本项目不对该事件中任何一方作对错评判，不评价谁对谁错，也不点名针对任何真实个人。它标注的是**语言现象**，不是**人的罪状**。

---

## 它能做什么

粘一个 B 站视频链接或 BV 号 → 扫描该视频的评论区 → **标出命中话术的评论 + 逐字证据原话 + 8 类标签**。

| 编号 | 名称 | 一句话 |
|---|---|---|
| **T1** | 和稀泥 | 「都别吵了」「各有各的道理」——把是非问题搅成态度问题 |
| **T2** | 假中立 | 摆出中立的姿态，实际把举证责任单方面压给一方 |
| **T3** | 消解·梗 | 用玩梗把严肃议题变成段子，讨论从此不可继续 |
| **T4** | 消解·轻描淡写 | 「多大点事」「上纲上线了吧」——把具体伤害降级成情绪 |
| **T5** | 扣帽·软色情 | 用性暗示给人贴标签，绕开论证直接贬值对方 |
| **T6** | 扣帽·性别 | 把议题归因到性别身份，用阵营替代论证 |
| **T7** | 信息茧房 | 「你们那个圈子就那样」——用来源否定内容 |
| **T9** | 反饭圈 | 以「反饭圈」之名行扣帽之实，姿态正确、论证为零 |

**T8（胜利后劝和）已砍掉，不训练、不展示。** 理由：在本事件里这种话术**几乎不存在**——全量语料里样本仅 **2 条**，而且都被人工标注判为**误标**。留着一个没有正例的类，只会让模型多一个随机输出口，所以直接砍掉。规则包 `rules/event-deepseek.json` 里仍保留 T8 定义（历史遗留），但模型和页面都只用上面这 8 类。

每条命中都会带**逐字证据原话**（模型模式下是「抄回原文的那句话」，规则模式下是**命中的规则原文 + 字符区间**），你可以点开原文逐条核对。

## 30 秒上手

前置：**Node.js ≥ 20.19**（内置 `fetch` 需要）。**零 npm 依赖，不用 `npm install`。**

```bash
git clone https://github.com/Aolibibi/spinlens.git
cd spinlens
node server.js
```

然后浏览器打开 **<http://127.0.0.1:8787>**，粘一个 B 站视频链接或 BV 号，点「开始扫描」。

服务只监听 `127.0.0.1`，别人访问不到，**不上传任何数据**。

Windows 用户也可以双击 `启动.cmd`：开一个黑窗口、自动拉起本机服务并打开浏览器，**关窗即停服务、释放显存**（本地模型引擎占的那点显存会跟着进程一起没了）。

想要命令行版（纯规则、零模型）：

```bash
node huashu.js https://www.bilibili.com/video/BV1pWaY6mEcM/
node huashu.js --demo        # 不联网，用内置 12 条示例语料体验一下
```

> 核心库文件名 `huashu.js`、`server.js` 是**历史遗留**（项目曾用名 huashu-lens / 话术透镜）。
> 改名要牵动一整条 `require` / 启动脚本 / 文档引用链，风险大于收益，所以**文件名保留不动，只改产品名**。

## 三种引擎怎么选

网页右上角（引擎卡片）切换，默认是「🎯 本地微调模型」。**三种引擎的「表现形式的差异」是刻意做出来的**——它们不是同一份输出的三种皮肤：

| 引擎 | 显示形式 | 前置条件 | 成本 / 速度 |
|---|---|---|---|
| **🎯 本地微调模型**（默认） | **8 类概率条** + 阈值滑块高亮 | Python 3.10+、`torch` + `transformers`、**自备权重**（约 400MB，不随仓库发布） | 完全离线；单条 **约 10ms**（本机历史实测含开销约 40ms/条）；占约 1GB 显存 |
| **🤖 LLM 模式** | **类型徽章 + LLM 文字理由 + 逐字证据原话**（正文里把那句原话高亮）——**不出概率条** | 任意 OpenAI 兼容接口（baseUrl + apiKey + 模型名） | API token 费用；评论会发到**你自己填的那个接口**；没有概率，只有「像不像」 |
| **📐 决策模型模式** | **8 类概率条**（与本地模型一致），阈值滑块可调 | Jev / TypeSafe System One 的 key（默认端点 `https://api.typesafe.ai`，路径 `/v1/systemone`） | 按请求计费、官方**无 batch 端点**，请求数 ≈ 评论数 |

- **本地微调模型**：读的是每个类型独立的 `P(正例)`，门槛由阈值滑块决定——**它是概率条**。
- **LLM 模式**：读的是模型的自然语言判断，**判定必须能把证据逐字抄回原文**，抄不回的一律丢弃（这就是「逐字证据原话」的意义）；不显示概率，因为大模型给的数字不是校准概率。
- **决策模型模式**：读官方返回的 **`P(true)` 校准概率**（`answers.<类型id>.noul`），**不读 `top_probability`**——后者是「获胜选项」的概率，不是 P(true)，拿它当 P(true) 会把每一类都判成命中。显示形式与本地模型一致（概率条）。

**命令行 / 规则引擎仍然在**：`node huashu.js <BV号>` 走的是零依赖的规则匹配（正则 + 词表），秒出、完全可复现，也是「零 npm 依赖」这句话的来源。它召回低（见下面「诚实的准确率」），但适合先跑一遍看看格式。

**local 引擎怎么指 Python**（没装 Python 也完全不影响另外两种引擎）：

```bash
# 方式一：环境变量指到你的 python
set HUASHU_PY=<你的 python.exe 完整路径>          # Windows cmd
export HUASHU_PY=/usr/bin/python3                 # macOS / Linux

# 方式二：把 python_embeded/ 放在项目同级目录，启动器会自动探测
```

权重目录用 `HUASHU_MODEL` 指定，默认找 `lab/train/runs/all20/best`。

## ⭐ 训练方法与思路

### 为什么走弱监督微调（而不是继续堆规则）

- **手写规则全量召回只有 0–12%**：规则能覆盖的永远是最表层的固定搭配，稍微换个说法就漏。
- **中文零样本判决四路实测**都只有 **4–20% 精确率**（DeepSeek API 20%、Jev-Style 5.6–8.2%、Erlangshen 零样本 4.3–5.1%、规则 0–12%）。
- 结论：**先造弱标签，再微调一个小的中文编码器**——用大模型的「判断能力」去批量造标签，用小编码器的「成本」去把判断变成离线、免费、可复现的能力。

### 数据

- 自采 B 站评论 **19,903 条 / 97 个视频**。
- **语料不随仓库发布**（隐私与合规）：涉及真实用户发言，进不了公开仓库。

### 打标

- 用 DeepSeek 按最初那套 T1–T9 定义逐条判定，共标 **3785 条**（去重后）。
- 要求模型**逐字引用证据**，并做**机械校验**：证据在原文里找不到就整条丢弃。实测**证据逐字命中率 100%**（因为抄不回的都被丢了）。
- **正例率 15.8%**。

### ⭐ 关键方法洞察：候选池的选法比数量重要得多

同一套打标流程、同一个模型，**只换「喂给它的池子怎么选」，正例率差了 6 倍**：

- 按**点赞排序**取的池子 → 正例率 **9.6%**
- 按**「劝和」等语义锚点**挖的池子 → 正例率 **57.1%**

**差 6 倍。** 换句话说：**不是数据不够，是选池子的方式不对。** 你不需要一百万条评论，你需要一批「大概率有话术」的评论。这条比后面任何超参都值钱。

### 训练配置

- 基座：**Erlangshen-Roberta-110M**
- 任务：**8 类多标签**（8 个独立二分类头，不是 9 分类 softmax）
- 损失：**BCEWithLogitsLoss**
- 不均衡：**`pos_weight = sqrt(neg/pos)`**（不用 `neg/pos`：稀有类会得到几百上千的权重，梯度被彻底支配，模型对稀有类输出接近 1，精确率直接归零）
- `max_len 256`、`batch 32`、`lr 3e-5`、**全参数解冻**、`20 epochs`、`seed 42`
- **防泄漏**：把用于验收的 **200 条人工标注的 rpid 从训练集彻底剔除**——否则就是拿考卷当课本。

### ⭐ 三个失败教训（诚实资产）

这三条都是真金白银烧出来的，写出来是为了让你少烧一遍：

1. **冻结编码器、只训分类头** → 可训练参数仅 **0.01%**（6921 个），5 轮后退化成**「全判负」**：它学会了对所有输入说「不是」，因为在正例率只有个位数的数据上，这是最快降 loss 的路。
2. **只解冻最后 2 层**（**14.4%** 参数）→ 输出接近常数，**教科书样本都不亮**；此时那个 **「18.8% 精确率」是噪声撞出来的假象**——不是模型学会了，是评测集太小、随便蒙都能蒙出这个数。
3. **全解冻 + 20 轮** → 教科书样本 **8/8 全中**、正负样本区分度 **70–500 倍**，这才是真的学到了东西。

**一句话**：小模型微调里，「训多少参数」和「训多少轮」不是调优项，是**能否学到**的开关。

## 诚实的准确率（先读这段）

不想让任何人对着这份 README 产生错误期待，所以把**全部**已知数字摊在这里，一个都不美化。

| 方案 | 实测结果 | 备注 |
|---|---|---|
| **本地微调模型**（人工验收） | **精确率 P = 29.4% / 召回率 R = 55.6%** | 验收集**只有 8 条正例**，样本极小，置信区间很宽 |
| **产品规则**（正则 + 词表） | 召回 **0–12%** | 在均匀随机 200 条样本上召回 **0%（0/4）** |
| **DeepSeek API**（LLM 模式） | 精确率 **20%** | 通用大模型直接判，中文修辞判别力一般 |
| **Jev-Style**（决策模型模式） | **5.6–8.2%** | 官方自述 CJK 非强项，需自行调阈值 |
| **Erlangshen 零样本**（未微调） | **4.3–5.1%** | 没微调基本等于没工作 |

**还有一个更根本的问题：标注本身就不牢。** 三方独立标注者之间的一致性只有
**Krippendorff α = −0.036**（比随机还差）。也就是说，「哪条评论算话术」这件事，
连人类之间都对不齐——**因此本项目无法宣称任何「绝对准确率」，上面所有数字都只能当量级参考。**

### 结论（一句话）

> **只能当粗召回源，必须人工复核。**
> 它的正确用法是帮你**把两万条评论缩到两百条**，不是替你下结论。
> 不要拿它的输出去指责任何人。

## 已知限制

- **只支持 B 站**（bilibili.com）。没有微博 / 知乎 / 小红书。
- **模型与规则输出都不一定准确**，上面那节已经写了数字，不再重复。
- **语料不随仓库发布**：训练语料、人工标注、模型权重都在开发者的 `lab/` 下，已在 `.gitignore` 排除。
- **人工标注者之间一致性极低**（三方 α = −0.036），所以**绝对准确率无法宣称**。
- **不抓楼中楼**（只抓主评论），但摘要里会同时显示「总评论数」，不会让你以为抓漏了。
- **不判断立场、不判断真假**，只标「这段话像不像某类话术」。
- 触发 B 站风控时会拒绝出报告（故意的，避免「平静地打出一份错报告」）。

## 输出怎么看

### 终端摘要

```
抓取  主评论 1035 条｜总评论 3631 条（含楼中楼 2596）｜2.4s｜0 错误
识别  命中 17 条 (1.6%)｜规则 event-deepseek｜阈值 0.6
T1   和稀泥型        4 条  ████
T7   信息茧房型      5 条  █████
```

- **主评论**是真正被分析的条数；**总评论**含楼中楼（本工具不抓楼中楼，两个数字不一样是正常的）。
- 出现 `⚠ 达到 --max-comments 上限` 说明没抓完。
- 出现 `⚠ 只拿到 3 条…疑似风控降级`，**这份结果不可用**（工具默认拒绝出报告）。

### CSV

| 列 | 含义 |
|---|---|
| `msg` | 评论原文 |
| `hits` | 命中了哪些类型、各多少分，例如 `T1:0.8;T7:0.8` |
| `evidence` | **命中的规则原文**和字符区间，例如 `T1:pattern:(没(必要…))@12-18` |
| `jump_url` | B 站给的评论永久链接，点一下就能跳回原文 |
| `max_score` | 最高分 |

CSV 第一条以 `#` 开头的是免责声明。文件是 **UTF-8 with BOM**，双击用 Excel 打开不会乱码。

## 踩坑提醒（实测踩出来的）

| 现象 | 原因 / 怎么办 |
|---|---|
| Excel 打开乱码 | 别用 `> 结果.csv` 重定向（Windows 会写成 UTF-16）。用 `--out` 让程序自己写 |
| `ECONNREFUSED` / `ETIMEDOUT` | Node 自带 `fetch` **不读系统代理**。请换直连网络 |
| 接口返回 `code=-352` | 触发风控。加大 `--delay`（比如 400），或过一会儿再来 |
| 只拿到 3 条 | 风控降级。工具会拒绝出报告——这是故意的 |
| 抓不到 / WBI 签名失败 | B 站改了签名算法。签名逻辑集中在 `huashu.js` 的 Fetcher 一节，等更新 |
| 想加自己的话术 | 复制 `rules/event-deepseek.json`，改完用 `--rules 你的文件.json` |

```bash
node huashu.js --selftest          # 规则原型自检（24 条夹具）
node tests/eval.js                 # 混淆矩阵：20 条虚构样本（随仓库发布，可直接跑）
node tools/regress.cjs             # 改规则时的第一道闸门：缺数据时自动跳过并提示
node tests/webtest.mjs             # 网页版 API 自测（需先启动 server.js；模型部分用假模型）
node tools/preflight.cjs           # 发布前泄漏自检
node tools/package-release.mjs     # 打包发布版到 dist/spinlens-v1.0.0/
```

> `tools/regress.cjs` 需要本地真实语料（`lab/` 下，不随仓库发布）。
> 自备数据后用 `HUASHU_DEV_RAW` / `HUASHU_HOLDOUT_CSV` 指过去即可，详见该文件头注释。

**关于自带示例数据的诚实声明**：`huashu.js` 的 `--selftest` 24 条夹具与 `--demo` 12 条示例，
是从真实语料里摘的**短句片段**（不含用户名 / 评论 ID / 链接），用作回归夹具。
如果你希望连这些也换成完全虚构的句子，提 issue。
